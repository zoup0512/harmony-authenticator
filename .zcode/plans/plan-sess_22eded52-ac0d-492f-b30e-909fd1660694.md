## 审阅结论
已阅读账户存储、首页、添加页面、OTP 引擎、URI 解析、Base32、启动入口及测试脚本，确认以下问题：
- `OtpUri.ets` 未验证 Base32 密钥；未知算法静默回落为 SHA1；小数位数、非安全整数计数器等参数可能被接受。
- `AddAccount.ets` 解析回填将非 6/8 位和非 30/60 秒参数静默改成默认值；名称、服务、密钥输入框未绑定回填状态；HOTP 预览错误调用 TOTP。定时更新的状态未被预览读取。
- `Index.ets` 每 250 毫秒重新排序、解码密钥并计算全部验证码；页面隐藏时缺少明确的定时器暂停；复制提示的旧超时会干扰连续复制。
- `AccountStore.ets` 未等待 `flush()`，异步写入失败无法传给界面；初始化失败仍标记已加载，损坏 JSON 被当作空列表，后续保存可能覆盖原数据；返回内部可变账户，且 nextId 未与已有 ID 校准。
- 现有测试主要覆盖底层摘要与 computeCode，没有覆盖真实账户包装接口、URI 和存储失败行为。

## 实施范围
### 1. 输入与验证码正确性
- 统一校验算法、位数、周期及非负安全整数计数器，非法输入明确报错，不静默改参。
- URI 解析校验密钥、编码和关键参数，HOTP 要求有效 counter；保留现有引擎可支持的整数位数和周期范围。
- 修复表单状态回填，保留导入的非默认位数和周期并正确展示，避免核对后保存改变验证码参数。
- 根据账户类型计算预览，确保 TOTP 时间和倒计时使用同一响应式时间值；HOTP 不展示时间倒计时。
- OTP 引擎增加参数边界检查，避免输出 NaN 或基于截断计数器的验证码。

### 2. 存储可靠性
- 序列化存储变更，等待持久化成功后再发布账户状态；界面捕获失败并显示错误，保存期间阻止重复提交。
- 加载失败或数据损坏时禁止写入，不自动清空或覆盖原数据；界面明确显示加载失败。
- 校验反序列化结构和账户字段，根据已存在的最大 ID 校准 nextId，并检查计数器递增上限。
- 复用现有 cloneAccount，避免将内部可变记录暴露给调用方，减少重复字段拷贝。

### 3. 首页性能与生命周期
- 按账户参数及 TOTP 时间片/HOTP 计数器缓存验证码，倒计时刷新不重复做 HMAC；账户变更时刷新数据和失效缓存。
- 页面隐藏时停止刷新，重新显示时立即同步；页面销毁时清理订阅、缓存及复制提示定时器。
- 修复连续复制时旧超时提前清除提示的问题。

### 4. 回归验证
- 扩展 Node 测试脚本，保留 RFC 向量及 crypto 交叉验证，补充真实 totp/hotp 接口、SHA256 TOTP、URI 解析/往返和非法参数边界测试。
- 使用隔离的 Preferences 替身验证存储失败、损坏数据保护、ID 校准、并发变更及防御性拷贝；不接触真实用户账户数据。
- 执行测试和 DevEco Hvigor debug 构建，修复实际出现的 ArkTS 编译问题。
- 最终报告实际修改、测试结果以及尚未验证的真机交互。
